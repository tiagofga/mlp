## Recommended Agent Roles

Use these roles as mental models or future agent definitions when splitting work.

## C++ Core Agent

Focus:

- matrix operations
- dense layer behavior
- activation/loss implementation
- optimizer correctness

Primary files:

- `include/matrix.hpp`
- `include/layer.hpp`
- `include/dense.hpp`
- `include/activations.hpp`
- `include/loss.hpp`
- `include/optimizer.hpp`
- `src/dense.cpp`
- `src/activations.cpp`
- `src/loss.cpp`
- `src/optimizer.cpp`

Verification:

```bash
cmake --build build
ctest --test-dir build --output-on-failure
```

## Test And Quality Agent

Focus:

- focused unit tests
- gradient checks
- integration tests
- duplicate test helper cleanup

Primary files:

- `tests/`
- `tests/test_helpers.hpp`
- `tests/gradient_check.hpp`

Rules:

- Reuse `tests/test_helpers.hpp` for matrix/vector assertions.
- Prefer small deterministic tests with fixed seeds.
- Keep training tests bounded so local and CI runs stay fast.

## Backend Performance Agent

Focus:

- OpenMP path
- BLAS path
- CUDA path
- dense benchmark expectations

Primary files:

- `include/matrix.hpp`
- `include/cuda_ops.hpp`
- `src/dense.cpp`
- `src/cuda_ops.cu`
- `benchmarks/dense_blas_benchmark.cpp`
- `CMakeLists.txt`

Verification:

```bash
cmake -S . -B build-omp -DMLP_ENABLE_OPENMP=ON
cmake --build build-omp

cmake -S . -B build-blas -DMLP_ENABLE_BLAS=ON
cmake --build build-blas
./build-blas/mlp_dense_benchmark --min-speedup 2.0
```

CUDA verification requires a local CUDA toolkit:

```bash
cmake -S . -B build-cuda -DMLP_ENABLE_CUDA=ON
cmake --build build-cuda
```

## Collaboration Rules

- Keep generated build directories out of reviews.
- Avoid changing public API without updating docs.
- Preserve C++17 compatibility.
- Prefer small, reviewable changes.
- Run CTest after source changes.
